FullShot is a screenshot utility; capturing runs entirely on-device and needs no account. There are no accounts to sign in to and no test credentials to provide: the package carries the FullShot Pro account check, and Pro sign-in is not enabled in this version, so that check never runs.

To exercise the add-on: open any web page, click the FullShot toolbar icon, and choose Full page / Visible / Region / Element. The capture opens in the extension's own result page, where it can be annotated, redacted, beautified, and exported as PNG / JPEG / WebP / PDF.

Notes for review:
- No remotely hosted code. Every script is a local relative path inside the package; there is no eval, no new Function, no CDN, and no WASM.
- Capturing contacts no server. The only network calls are the Pro account check's, to the destinations tool.json policy.networkAllowlist names.
- data_collection_permissions declares no REQUIRED collection and one OPTIONAL type, authenticationInfo, for the Pro account check. Pro sign-in is not enabled in this version, so that permission is never requested and FullShot collects nothing.
- Broad host access is declared as an OPTIONAL host permission and is never requested at install. It is requested at runtime, from a user gesture, only when the user enables cross-origin frame expansion (Options) or Batch URL capture. Declining leaves all other functionality working.
- The optional PII redaction feature scans page text locally and paints opaque blocks over matches. Detected values are never stored, indexed, or sent.
- In Firefox the background runs from background.scripts (pages/db.js, pages/batch.js, vendor/core/entitlement-client.js, pro/account.js, background.js); background.js guards its importScripts calls behind a typeof check, because importScripts exists only in a service worker.
- permissions.request is called only from user gestures (the Options toggle, the popup capture click, and Batch "start").
- The code ships unminified and unobfuscated; no build step or source archive is needed for review.
